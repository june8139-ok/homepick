## 개요

본 문서는 **대한민국 부동산 의사결정 플랫폼**의 관리자(Admin) 콘솔 요구사항을 정의한다. Admin은 단지·계약조건·예약·후기·광고·사용자·AI·사이트 설정을 운영·감독하는 내부 도구이다.

### Admin 사용자 역할 — 추후 상세 정의

| 역할 | 설명 |
|------|------|
| Super Admin | 전체 메뉴 접근, 권한 부여 |
| Operator | 일상 운영(예약, 후기, 인증 심사) |
| Editor | 단지·계약조건·콘텐츠 편집 |
| Viewer | 조회 전용 |

## 1. Dashboard

### 목적

플랫폼 전반의 **운영 현황을 한눈에 파악**하고, 처리가 필요한 항목(심사 대기, 신고, 예약 등)으로 빠르게 이동할 수 있는 Admin 홈 화면을 제공한다.

### 기능

| 기능 | 설명 |
|------|------|
| 핵심 지표 요약 | 등록 단지 수, 오늘 검색 수, 활성 예약, 미처리 심사 건수 등 |
| 처리 대기 큐 | Verified Buyer 승인 대기, 후기 신고, 예약 변경·취소 요청 |
| 최근 활동 로그 | 단지 수정, 계약조건 변경, 관리자 조치 이력 |
| 빠른 이동 | 각 관리 메뉴(§2~§10) 바로가기 |
| 기간별 통계 | 일·주·월 단위 트렌드 (추후 차트 상세 정의) |

### 예상 워크플로

1. 관리자가 Admin에 로그인하면 Dashboard가 기본 landing 페이지로 표시된다.
2. 상단 또는 카드 영역에서 **미처리 건수**를 확인한다.
3. 「Verified Buyer 5건 대기」 등 알림을 클릭하면 해당 관리 화면(§5)으로 이동한다.
4. 일일 운영 시 Dashboard → 대기 큐 처리 → 필요 시 각 상세 메뉴 순으로 업무를 진행한다.

## 2. Apartment Management

### 목적

플랫폼에 노출되는 **아파트 단지 정보**를 등록·수정·비공개 처리하여, 사용자-facing 상세 페이지(Apartment Detail)의 기준 데이터를 관리한다.

### 기능

| 기능 | 설명 |
|------|------|
| 단지 목록 | 검색·필터(지역, 분양 상태, 공개 여부), 정렬, 페이지네이션 |
| 단지 등록 | 단지명, 주소, 세대수, 준공(예정)일, 브랜드, 분양 상태 등 |
| 단지 수정 | 기본 정보·위치·평면도·이미지·태그 업데이트 |
| 공개/비공개 | 노출 중단, 초안 저장 |
| 미디어 관리 | 대표 이미지, 갤러리, 평면도 업로드·순서 변경 |
| 일괄 작업 | (향후) CSV 임포트, 다중 상태 변경 |

### 예상 워크플로

1. **신규 단지 등록**: 「단지 추가」 → 필수 정보 입력 → 이미지·평형 정보 등록 → **미리보기** → 공개
2. **정보 수정**: 목록에서 단지 검색 → 상세 편집 → 저장 시 변경 이력 기록
3. **분양 종료 처리**: 분양 상태를 「분양완료」 등으로 변경 → 검색·상세 노출 정책에 반영
4. **오류 대응**: 사용자 문의 또는 내부 QA에서 오류 발견 → 수정 → (필요 시) 공지

## 3. Contract Condition Management

### 목적

단지별 **분양가·할인·옵션·특약 등 계약조건**을 관리하고, 변경 시 **타임스탬프와 이력**을 남겨 사용자에게 「실시간 계약조건 변경」으로 노출한다. (PRD §5.3)

### 기능

| 기능 | 설명 |
|------|------|
| 조건 목록 | 단지별 현재 적용 중인 계약조건 조회 |
| 조건 등록·수정 | 분양가, 할인율, 옵션 패키지, 특약 문구, 적용 기간 |
| 변경 이력 | 누가·언제·무엇을 변경했는지 audit log |
| 즉시/예약 반영 | 저장 즉시 공개 또는 지정 일시에 자동 반영 |
| 버전 비교 | 이전 조건과 diff 확인 (추후 UI 상세) |
| 알림 연동 | (향후) 관심 단지 등록 사용자에게 조건 변경 알림 |

### 예상 워크플로

1. 분양사·시행사로부터 **조건 변경 안내**를 수신한다.
2. Admin → 해당 단지 → Contract Condition Management 진입
3. 새 조건 입력 또는 기존 항목 수정 → **적용 일시** 설정
4. 저장 시 **변경 이력** 자동 기록 → 사용자 상세 페이지에 최신 조건 + 변경 시각 노출
5. 중대한 변경(대폭 할인 등)은 Dashboard 또는 별도 검토 플로우 — 추후 정의

## 4. Reservation Management

### 목적

사용자의 **모델하우스·현장 방문 예약**(PRD §7)을 조회·확정·변경·취소하고, 현장 운영에 필요한 일정·수용 인원을 관리한다.

### 기능

| 기능 | 설명 |
|------|------|
| 예약 목록 | 단지·날짜·상태(대기/확정/취소/완료) 필터 |
| 예약 상세 | 방문자 이름, 연락처, 인원, 문의 사항 |
| 슬롯 관리 | 단지별 방문 가능 일시, 시간대별 정원 |
| 확정·거절 | 예약 요청 승인 또는 사유와 함께 거절 |
| 일정 변경 | 관리자 또는 사용자 요청에 따른 재배정 |
| 알림 발송 | 확정·리마인더·취소 SMS/이메일 (채널 추후 정의) |
| 현장 체크인 | (향후) 방문 완료 처리, no-show 기록 |

### 예상 워크플로

1. 사용자가 단지 상세에서 방문 예약을 신청하면 목록에 **「대기」** 상태로 적재된다.
2. 운영자가 슬롯·정원을 확인 후 **확정** → 사용자에게 알림 발송
3. 정원 초과 또는 휴무일 요청 시 **거절** + 사유 전달, 대안 일정 제안(수동)
4. 당일 **방문 완료** 처리(또는 no-show) → (향후) 방문 후기 유도와 연동
5. 단지별 **슬롯 템플릿**을 주기적으로 갱신(분양 기간, 공휴일 반영)

## 5. Verified Buyer Approval

### 목적

실제 **계약을 완료한 사용자**의 인증 신청을 심사하여, 승인 시에만 **Verified Buyer** 뱃지를 부여한다. 미승인 사용자에게는 뱃지가 부여되지 않는다. (PRD §9)

### 기능

| 기능 | 설명 |
|------|------|
| 심사 대기 큐 | 신규·재제출 인증 건 목록, 대기 시간·우선순위 |
| 제출 자료 열람 | 계약서 1면, 확정 문자, 계약 정보 등 |
| 단지·사용자 매칭 | 신청 단지와 자료 내 단지명·동·호 일치 여부 확인 |
| 승인 | Verified Buyer 뱃지 부여 (단지 단위) |
| 거절 | 사유 선택·입력, 사용자에게 안내 |
| 추가 자료 요청 | 보완 요청 후 「보류」 상태 |
| 뱃지 회수 | 계약 취소·해지·위조 확인 시 뱃지 제거 |
| 심사 이력 | 처리자, 일시, 결과, 코멘트 |

### 예상 워크플로

1. 사용자가 후기 작성 또는 마이페이지에서 **계약 인증** 신청 및 자료 업로드
2. Dashboard·§5 큐에 **「심사 대기」** 건으로 표시
3. 운영자가 제출 자료 확인:
   - **Contract first page**: 당사자·단지 식별 정보와 DB 단지 일치
   - **Confirmation message**: 발신처·단지명·일자 검증
   - **Contract information**: 계약번호·계약일 등 교차 확인
4. **승인** → 해당 사용자·단지에 Verified Buyer 부여 → 이후 후기에 뱃지 표시
5. **거절** → 사유 통지 → 재제출 가능 여부에 따라 사용자 재신청
6. 자료 불충분 시 **추가 자료 요청** → 보류 → 보완 후 3번부터 재심사

## 6. Review Management

### 목적

사용자 **후기**(계약·방문 등)를 조회·노출 제어·신고 처리하여, 플랫폼 콘텐츠 품질과 법적 리스크를 관리한다. (PRD §8)

### 기능

| 기능 | 설명 |
|------|------|
| 후기 목록 | 단지·유형·Verified Buyer 여부·신고 상태 필터 |
| 후기 상세 | 본문, 평점, 작성자, 작성일, 뱃지 표시 여부 |
| 노출/숨김 | 부적절 후기 비공개 처리 |
| 신고 처리 | 신고 사유, 처리 결과(유지/삭제/경고) |
| 관리자 답변 | (선택) 공식 입장 또는 안내 댓글 |
| 일괄 모더레이션 | 키워드·스팸 필터 (향후) |
| 통계 | 단지별 후기 수, 평균 평점, 인증 후기 비율 |

### 예상 워크플로

1. Dashboard에서 **신고 접수** 또는 키워드 알림 확인
2. Review Management에서 해당 후기 열람 → Verified Buyer 여부·작성 이력 확인
3. **유지**: 신고 기각, 후기 계속 노출
4. **숨김/삭제**: 운영 정책 위반(허위, 비방, 개인정보) → 조치 + (필요 시) 작성자 제재(§8 User Management)
5. 분쟁·법적 이슈 시 **법무 검토** 후 처리 — 내부 에스컬레이션 플로우 추후 정의
6. Verified Buyer 후기는 **뱃지 회수**(§5)와 연동 검토

## 7. Advertisement Management

### 목적

플랫폼 내 **광고·프로모션** 영역(배너, 추천 단지, 스폰서 노출 등)을 등록·기간·타겟 설정으로 관리하고, 수익·노출 정책을 운영한다.

### 기능

| 기능 | 설명 |
|------|------|
| 광고 목록 | 진행 중·예정·종료 캠페인 |
| 광고 등록 | 이미지/카피, 링크 URL, 노출 위치(홈, 검색 결과, 상세 등) |
| 기간·스케줄 | 시작·종료 일시, 요일·시간대 (추후) |
| 타겟팅 | 지역, 분양 상태, (향후) 사용자 세그먼트 |
| 우선순위·가중치 | 동일 슬롯 내 노출 순서 |
| 성과 조회 | 노출 수, 클릭 수, CTR (측정 방식 추후 정의) |
| 승인 워크플로 | (선택) Editor 등록 → Super Admin 승인 후 게재 |

### 예상 워크플로

1. 영업·마케팅에서 **캠페인 요청**(단지, 기간, 슬롯) 접수
2. Admin → Advertisement Management → **새 광고** 생성
3. 소재·링크·노출 위치·기간 입력 → (정책상) **미리보기** 확인
4. **게재** → 기간 내 사용자-facing 영역에 노출
5. 종료일 도래 또는 수동 **중단** → 목록 상태 「종료」
6. 월말 **성과 리포트** 확인 → 다음 캠페인 기획

## 8. User Management

### 목적

플랫폼 **회원(사용자)** 계정을 조회·상태 관리·제재하고, Admin 계정(§개요 역할)과 구분하여 운영한다.

### 기능

| 기능 | 설명 |
|------|------|
| 사용자 목록 | 검색(이메일, 닉네임, ID), 가입일, 상태 |
| 사용자 상세 | 프로필, Verified Buyer 이력, 후기·예약 이력 링크 |
| 계정 상태 | 활성, 정지, 탈퇴 |
| 제재 | 기간 정지, 영구 정지, 후기 작성 제한 |
| 탈퇴 처리 | GDPR/개인정보보호법에 따른 데이터 처리 — 추후 정의 |
| Admin 계정 | Admin 사용자 생성·역할 부여·비활성화 (Super Admin) |
| 접근 로그 | (향후) 사용자·Admin 주요 행위 audit |

### 예상 워크플로

1. **CS 문의** 또는 Review/Verified Buyer 처리 중 이상 계정 발견
2. User Management에서 사용자 검색 → 활동 이력(후기, 예약, 인증) 확인
3. 경미한 위반: **경고** + 후기 수정 요청
4. 반복·중대 위반: **기간 정지** 또는 **영구 정지** → 로그인·후기 작성 차단
5. **탈퇴 요청** 시 개인정보 삭제·보관 정책에 따라 처리
6. Super Admin이 **새 운영자 Admin 계정** 생성 및 Operator/Editor 역할 부여

## 9. AI Management

### 목적

**AI 단지 비교**(PRD §6) 및 (향후) 인증 보조·후기 요약 등 AI 기능의 **설정·모니터링·품질 관리**를 Admin에서 수행한다.

### 기능

| 기능 | 설명 |
|------|------|
| 비교 설정 | 비교 가능 항목, 최대 비교 단지 수, 출력 형식(표/요약) |
| 프롬프트·모델 | (내부) 시스템 프롬프트 버전, 모델 선택 — Super Admin 제한 |
| 사용량 모니터링 | API 호출 수, 토큰, 비용 추정 |
| 품질 검수 | 샘플 비교 결과 검토, 부적절 출력 플래그 |
| 인증 보조 | (향후) Verified Buyer 자료 OCR·매칭 결과 → §5 심사 참고 |
| 캐시·재생성 | 동일 단지 조합 결과 캐시 TTL, 수동 invalidation |
| 면책·고지 | 사용자-facing AI 고지 문구 편집 (Site Settings와 중복 시 통합) |

### 예상 워크플로

1. **AI Comparison** 신규 항목(예: 학군 점수) 추가 요청 → AI Management에서 비교 항목 ON
2. 프롬프트/모델 변경 시 **스테이징 테스트** → 샘플 단지 2~3개로 출력 검수
3. **프로덕션 반영** → 사용량·오류율 Dashboard 연동 모니터링
4. 사용자 **「부정확한 비교」** 신고 접수 → 해당 로그 조회 → 프롬프트 또는 데이터 소스 수정
5. (향후) Verified Buyer **자동 매칭 제안** → 운영자는 §5에서 최종 승인만 수행
6. 월간 **비용·품질 리포트** 검토

## 10. Site Settings

### 목적

플랫폼 **전역 설정**—브랜딩, SEO, 정책 문구, 알림 채널, 유지보수 모드 등—을 Admin에서 일원화하여 관리한다.

### 기능

| 기능 | 설명 |
|------|------|
| 기본 정보 | 사이트명, 로고, 파비콘, 연락처 |
| 홈·랜딩 | 메인 타이틀·서브타이틀, 기능 카드 문구 (PRD §2 연동) |
| SEO | 메타 title/description, OG 이미지 |
| 정책 페이지 | 이용약관, 개인정보처리방침, AI·후기 고지 문구 |
| 알림 설정 | SMS/이메일 발신 프로필, 템플릿 (§4·§7 연동) |
| 유지보수 모드 | 공사 중 페이지, Admin IP 화이트리스트 |
| 지역·코드 | 시도·시군구 코드, 분양 상태 enum 등 마스터 데이터 |
| 기능 플래그 | (향후) 기능 ON/OFF without deploy |

### 예상 워크플로

1. **브랜드 변경** 또는 홈 카피 수정 → Site Settings → 홈·랜딩 섹션 편집 → 저장 → 사용자 홈 즉시 반영
2. **약관 개정** → 법무 검토본 업로드 → 시행일 설정 → 사용자 동의 플로우 (추후) 연동
3. **장애·점검** → 유지보수 모드 ON → 점검 완료 후 OFF
4. 신규 **지역 코드** 또는 분양 상태 추가 → 마스터 데이터 갱신 → Apartment Management 필터에 반영
5. 분기별 **SEO·OG** 점검 및 업데이트
